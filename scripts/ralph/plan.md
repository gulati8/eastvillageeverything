# Admin plan: slugs, collapsible sections, AI editorial

Changes to the Next admin (`apps/admin/`) asked for by the user on 2026-11-03
after using the admin for real: the tag slug field is confusing and should not
be typed by a person; the five "Generate AI text" buttons have never worked;
and the place edit page is too long, so its sections should collapse. This
file is the work queue. The checkboxes are the only record of progress. Facts
a later iteration needs go in `scripts/ralph/progress.txt`, not here. The
previous plan (photos and feedback) is archived in `scripts/ralph/archive/`.

Each task has a `Done when` line, which is the verification the agent must run
before ticking it. Tasks tagged `[HUMAN]` are done by a person, who ticks them.
`Blocked by` lists tasks that must be ticked first.

Decisions already made with the user, which the tasks below implement and no
task may revisit:

- **Slugs are derived, never typed.** A tag's `value` is generated from its
  display name on create and regenerated from the display name on every save,
  with a `-2`, `-3` suffix when another row already has it. The form still
  shows the slug, as read-only text that updates live while the display name
  is typed, so the user can see it. Nothing stores a slug long-term: places
  link to tags by id, the website renders the dropdown and row classes from
  the database on each load, and the mobile app matches chip values against
  each place's tag list from the same API fetch. Neighborhoods get the same
  treatment so the two forms match. The legacy EJS admin (`src/views/admin/`)
  is not touched.
- **Sections collapse, with no memory and no summaries.** Every section on the
  place edit and new pages is collapsible. Photos and Basics start open;
  everything else starts closed. The state is not remembered anywhere (the
  user rejected per-browser persistence: the admin is place-centric, not
  field-centric) and a collapsed header shows only its title, no count or
  "empty" line (rejected as noise). Collapsed fields stay in the DOM and still
  submit, so Save never loses a hidden value. This reverses the previous
  plan's "no collapsing" decision at the user's request.
- **Generate uses Claude with its web search tool, not the Google Places
  API.** The user rejected Place Details calls on cost. Each click sends the
  place's name, address and what is on the form to `claude-sonnet-5-5` with
  the `web_search_20260209` server tool capped at 3 searches, and the model
  finds recent reviews and write-ups itself (web search is $10 per 1,000
  searches, so a click is a few cents all in). The key is `ANTHROPIC_API_KEY`,
  already in the root `.env` locally and set as the GitHub Actions secret
  `ANTHROPIC_API_KEY` on 2026-11-03 (`gh secret list` shows it); 3.2 makes
  the deploy workflow write it to prod like the Google key.
- **One section button plus per-field redo.** "Generate editorial" at the top
  of the Editorial section fills every blank field in one call and leaves
  filled fields alone. Each field keeps a small button that regenerates only
  that field, replacing its text. All five fields are generated: pitch,
  perfect, insider, vibe, crowd. Nothing is saved until the user presses
  Save. The copy follows the voice rules the launch plan used (see 3.2) and
  the model is told to leave a field blank rather than invent specifics when
  it finds nothing about the place.
- Mobile app code and the public API are out of scope.

## Phase 3: generate editorial

- [ ] **3.2 Generate route: Claude with web search writes the five fields.** Add `@anthropic-ai/sdk` to `apps/admin/package.json` (run `npm install` from the repo root so the workspace lockfile updates). Invoke the `claude-api` skill before writing the call; the facts that matter: model `claude-sonnet-5-5` (one exported constant `EDITORIAL_MODEL`), server tool `{ type: 'web_search_20260209', name: 'web_search', max_uses: 3, user_location: { type: 'approximate', city: 'New York', region: 'New York', country: 'US', timezone: 'America/New_York' } }`, structured output through `output_config.format` with a JSON schema whose five properties are nullable strings (`client.messages.parse` with `zodOutputFormat`, adding `zod` to the admin if it is not already a transitive dependency, or a raw JSON-schema format object), `max_tokens` 16000, no `tool_choice` (forced tool use is rejected on this model), no `temperature`, and handle `stop_reason: 'pause_turn'` by sending the turn back once. New `apps/admin/lib/editorial.ts` (pure, no SDK import, `node --test lib/editorial.test.mjs`): `EDITORIAL_FIELDS = ['pitch', 'perfect', 'insider', 'vibe', 'crowd']`, `buildEditorialPrompt({ place, fields })` returning `{ system, user }`, and `validateEditorial(fields)` returning a list of violations. The system prompt carries the voice rules from the archived launch plan 3.5: `pitch` is two sentences in a friend's voice about why you would go, grounded in what recent write-ups and reviewers actually praise or warn about, newest first; `perfect` completes "Perfect when…" in under 12 words, no prefix; `insider` is one concrete sentence (a dish, a seat, a time of day, a door policy, a card-only note) that a source actually mentioned; `vibe` is three words joined by " · "; `crowd` is one short phrase about who is there; never quote a source verbatim, never mention Google, Yelp, reviews, stars or ratings, never use "hidden gem", "nestled", "vibrant", "elevated" or exclamation marks; use the hours and price tier given when they help; search for the place by name and address and prefer sources from the last two years; if nothing specific is found, write short neutral copy for `pitch` and `vibe` and return `null` for `insider`, `perfect` and `crowd` rather than inventing; write only the fields asked for and return `null` for the rest. The user message carries name, address, cross street, neighborhood, website, tags, weekday hours from `hours_json`, price tier, specials, notes, and the current text of any editorial field not being generated (so a redo of one field stays consistent with the others). `validateEditorial` checks: exclamation marks, the banned words, `perfect` under 12 words, `pitch` exactly two sentences (same split rule as `scripts/ralph/editorial-append.mjs`), `vibe` three " · "-separated parts. New route `apps/admin/app/api/admin/generate/route.ts`, `runtime = 'nodejs'`, POST only: guard with `requireAdminRequest(req, { mutation: true })` (first statement, and add it to the "guards admin API routes explicitly" test in `lib/security.test.mjs`); body `{ place_id, fields: string[], form: { name, address, cross_street, url, specials, notes, pitch, perfect, insider, vibe, crowd } }` where `form` is the unsaved state of the page (it wins over the DB row for those keys; the DB row supplies tags, neighborhood, `hours_json` and `price_tier`); 400 when `place_id` is missing or `fields` is empty or has an unknown name, 404 when the place does not exist, 503 `{ error: 'Generate is not configured. Set ANTHROPIC_API_KEY.' }` when the env var is blank (check before building the client). Call the model once; if `validateEditorial` reports violations, call once more with the violations listed and "fix only these"; return `{ fields: { pitch, perfect, insider, vibe, crowd }, searches, warnings }` with `null` for fields not requested, `searches` from `usage.server_tool_use.web_search_requests`, and `warnings` as any violations left after the retry. Map SDK errors: `AuthenticationError` → 503 "The Anthropic key was rejected.", `RateLimitError` → 429 "Claude is busy. Try again in a minute.", other `APIError` → 502 with the SDK message, and a `refusal` stop reason → 422 "Claude declined to write this one." Log one line per call to stdout as `admin generate place=<id> fields=<a,b> searches=<n> in=<input_tokens> out=<output_tokens> ms=<n>`, never the text. Env wiring: add `ANTHROPIC_API_KEY=` to `apps/admin/.env.example` with a one-line comment; append the value from the root `.env` to `apps/admin/.env.local` by piping (`grep '^ANTHROPIC_API_KEY=' .env >> apps/admin/.env.local`), never echoing it; in `.github/workflows/deploy.yml` add `ANTHROPIC_KEY_B64` next to `GOOGLE_KEY_B64` and a matching `tee -a /srv/eve/.env` line; the secret already exists (`gh secret list`), so after this deploy prod's route is live (`deploy/docker-compose.prod.yml` needs no change: the admin service already reads `.env`). Push to deploy.
  Done when: `npm run build:packages && npx tsc --noEmit` at root, `cd apps/admin && npx tsc --noEmit && npm run test:security && node --test lib/editorial.test.mjs` pass; `grep -rn "ANTHROPIC" apps/admin/components apps/admin/app --include='*.tsx'` prints nothing (the key never reaches a client component); locally with the admin running and a session cookie (recipe in `progress.txt`), `curl -s -X POST -H 'Origin: http://localhost:3001' -H 'Content-Type: application/json' -b "connect.sid=<signed>" http://localhost:3001/api/admin/generate -d '{"place_id":"<a real local place id>","fields":["pitch","perfect","insider","vibe","crowd"],"form":{}}'` returns 200 with five populated fields (or `null` where the model found nothing) and `searches` between 1 and 3, and the same call without the cookie returns 401; paste the returned JSON for one place into `progress.txt` so the user can judge the voice; the deploy workflow passed; `curl -s -o /dev/null -w '%{http_code}' -X POST https://eastvillageeverything.nyc/admin/api/admin/generate` prints 401; `ssh ec2-user@100.29.233.41 'grep -c "^ANTHROPIC_API_KEY=sk" /srv/eve/.env'` prints 1.
