# Admin plan: photos and feedback

Fixes to the Next admin (`apps/admin/`) and the API that came out of user testing
on 2026-10-28, when a photo added to Upstate from a phone was uploaded to S3 twice
but never attached to the place, with no message on screen at any point. This
file is the work queue. The checkboxes are the only record of progress. Facts a
later iteration needs go in `scripts/ralph/progress.txt`, not here. The launch
plan this replaces is archived in `scripts/ralph/archive/`.

Each task has a `Done when` line, which is the verification the agent must run
before ticking it. Tasks tagged `[HUMAN]` are done by a person, who ticks them.
`Blocked by` lists tasks that must be ticked first.

Decisions already made with the user, which the tasks below implement and no
task may revisit:

- Every action in the admin reports its outcome through one feedback overlay.
  Nothing finishes silently, including validation failures that today `return`
  with no message.
- A photo saves itself the moment it is picked. There is no Save step for
  photos. The Save button keeps its name and saves the text fields only.
- A place can have many photos. The first one is the list thumbnail (admin
  list and mobile list). Ordering is by a "Make first" button, not drag.
- When a place has no uploaded photo, the Google photo stays the fallback
  everywhere, and the admin shows it labelled as Google's.
- No filtering on the admin list page. No collapsing of the edit page
  sections. The edit page keeps its sections in today's order, with the
  photos moved to the top.
- Mobile app code is out of scope. The API change is additive and the 1.0.0
  app keeps working. Swiping through multiple photos in the app is deferred
  (see the end of this file).
