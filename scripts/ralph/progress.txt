## Codebase Patterns
- Google photo proxy (3.7): `GET /api/places/:id/photo?size=thumb|hero|orig` in `src/routes/api.ts` serves a place's Google photo (`places.google_photo_name`, written by `scripts/enrich-places.ts` in both backfill and `--refresh`; `--refresh --force` ignores the 7-day staleness window) from Google's `/media` endpoint with Redis caching (`gphoto:<size>:<photo name>` + `:type`, 7-day TTL, logs `photo cache hit|miss place=<id> size=<size>`), or 302s to the admin upload when `photo_url` is set. The API fills `photo_url`/`photo_thumb_url`/`photo_hero_url` with absolute proxy URLs (origin taken from the request; `trust proxy` makes it https behind Caddy) whenever `photo_url` is null and `google_photo_name` is set, and the detail response adds `photo_attribution` (Google author name, null otherwise). The proxy is exempt from the shared `/api` limiter and has its own 600/min bucket. `GOOGLE_PLACES_API_KEY` reaches prod `/srv/eve/.env` from the GitHub Actions secret of the same name via `deploy.yml`. The shared ioredis client lives in `src/redis.ts`. 8 prod places have a Place ID but no Google photo (Angel's Share, Bar On A, Camp David NYC, Contrada, L'Apicio, Mark, Terroir, The Hard Swallow), so their photo fields stay null.
- Editorial copy (3.5) goes in `scripts/ralph/data/editorial.json` (committed). Add a batch with `node scripts/ralph/editorial-append.mjs <batch.json>`: it validates ids/names against `review-context.json`, rejects duplicates, empty fields, exclamation marks, banned words (hidden gem, nestled, vibrant, elevated, Google, review(s), star(s), rating(s)), `perfect` of 12+ words and a `pitch` that is not exactly two sentences, and appends only if every entry passes. `perfect` is the completion only (no "Perfect when" prefix; the admin label supplies it). Walk `review-context.json` in key order (sorted by name) with `node /tmp/dump.js A B`-style compact dumps; the 3.5 progress entries record which index ranges are done and which places were skipped as closed. Skip rule used so far: no Google hours AND newest review older than 2024, or zero reviews; list each skipped place under the 3.5 entry with the reason so the Done when count (`review-context` ids minus listed closed places) stays checkable.
- `scripts/ralph/data/review-context.json` (gitignored, 1.2 MB, written by `npm run review-context` / `scripts/pull-review-context.ts` in 3.4) holds Google review context for all 313 prod places, keyed by place id and sorted by name: our `name`, `address`, `cross_street`, `tags`, `hours` (Monday-first weekday lines), `price_tier`, plus `google.{rating,user_rating_count,editorial_summary,generative_summary,primary_type,reviews[]}` with reviews newest-first (`text`, `rating`, `publishTime`, `relativePublishTimeDescription`). On prod every row has `price_tier` and `cross_street` NULL, so those are null in every entry. The script resumes (skips ids already in the file; `--force` refetches) and only reads Postgres; it never writes anything from the file to the database.
- Static public pages (privacy, support) are plain Express routes in `src/routes/public.ts` rendering full-page EJS views in `src/views/public/` (no shared layout partial; `index.ejs` and `privacy.ejs` each carry the header). Page-specific prose styles live under `.row.main-content.page` at the bottom of `public/css/main.css`; the Dockerfile copies `public/` and `src/views/` so no build step is involved. Playwright e2e (`tests/e2e/`) is NOT in CI and its browsers are not installed on this laptop: `npx playwright install chromium` under Node 26 downloads fully, then stalls during extraction (twice, 10+ minutes each), so verify public pages by starting the server (`DATABASE_URL=postgres://eve:eve_dev_password@127.0.0.1:5435/eve_development REDIS_URL=redis://127.0.0.1:6381 SESSION_SECRET=x npx tsx src/server.ts`) and using curl. Support email for the app is `amit@gulatilabs.me` (5.1), hardcoded as `SUPPORT_EMAIL` in `src/routes/public.ts`.
- Google `hours_json.weekdayDescriptions` is Monday-first (index 0 = Monday, 6 = Sunday) while `period.open.day` and JS `getDay()` are Sunday-first; `todayHoursLabel()` in `apps/mobile/src/data/transformPlace.ts` does the `(etDay + 6) % 7` rotation in Eastern Time via `getETWeekday()` from `signals/hours.ts`. Any mobile test whose module transitively imports `signals/hours.ts` must start with `jest.mock('@eve/shared-types', () => ({ EVE_TIMEZONE: 'America/New_York' }))` because the shared-types `src/index.ts` re-exports with `.js` extensions that CommonJS Jest cannot resolve for a runtime value (type-only imports are erased and never hit this). Prod `hours_json` also carries `openNow` and `nextCloseTime` keys that are not in the `HoursJson` type; they are frozen at enrichment time, so never read them.
- `places.google_place_id` has a UNIQUE constraint (`places_google_place_id_key`). When Text Search resolves two rows to the same Google place (a duplicate listing such as "The Phoenix"/"Phoenix", or a wrong match on a neighbor), the second write fails with Postgres 23505 and the script marks that row `failed`; the log line is `DB write failed ... duplicate key`, not a Google error. 35 of the 38 failures in 2.7 were this. The backfill query is `google_place_id IS NULL`, so `failed` rows are retried automatically on the next `npm run enrich`; fix for 3.3 is delete the duplicate or correct the address, then re-run, with no status reset. Rows with a NULL `address` (Club Groove) are never selected by the backfill and stay `'pending'`.
