## Codebase Patterns
- Google Places: the enrich script (`scripts/enrich-places.ts`) uses Places API (New) only, whose service is `places.googleapis.com`; `places-backend.googleapis.com` is the legacy Places API and does not serve `places:searchText`. Both are enabled on project `eve-enrich-2026` and the `eve-enrich` key (`projects/496847463127/locations/global/keys/31d70efe-22d4-4cba-b95f-b7fed756e72c`) is restricted to both. `gcloud services api-keys create` prints the `keyString` in its operation output even with `--format`; redirect everything to `/dev/null` and get the name from `api-keys list` (which omits the key string).
- `apps/mobile` is a root npm workspace (`workspaces: ["packages/*","apps/*"]`), so any `npm install` / `npx expo install` run inside it resolves against the ROOT `package-lock.json` (`cd apps/mobile && npm prefix` prints the repo root). `apps/mobile/package-lock.json` is still tracked and is a CI cache key, so after a mobile dependency change regenerate it in isolation: copy `package.json` + `package-lock.json` to an empty temp dir, run `npm install --package-lock-only --ignore-scripts` there, copy the lock back. Commit both lockfiles.
- iOS build numbering is local: `apps/mobile/eas.json` has `cli.appVersionSource: local`, so `expo.ios.buildNumber` in `apps/mobile/app.json` is the only source of truth (11 is the last used). Bump it by hand before a release build. `eas build:version:get` fails on purpose under local source. `eas build:configure` has no `--non-interactive` flag in eas-cli 18.10.0 or 25.3.0; run it with `</dev/null` instead.
- In prod, Caddy sends `/admin*` on the `.nyc` hosts to `eve-admin` (Next), so the Express EJS admin at `/admin` is only reachable by hitting `eve-app` directly. The EJS place form links to the Next admin via `NEXT_ADMIN_URL` (default `http://localhost:3001`; `deploy.yml` writes `https://eastvillageeverything.nyc/admin` into `/srv/eve/.env`). Photo uploads exist only in the Next admin since 1.7.
- Local dev stack: `docker compose up -d postgres redis` publishes Postgres on `127.0.0.1:5435` and Redis on `127.0.0.1:6381` (not 5432/6379). The host Node is v26, which breaks the `node-pg-migrate` CLI (yargs `require` in ESM scope); run migrations in a Node 20 container on the compose network: `docker run --rm -v "$PWD":/app -w /app --network eve_default -e DATABASE_URL=postgres://eve:eve_dev_password@postgres:5432/eve_development node:20-alpine node node_modules/node-pg-migrate/bin/node-pg-migrate up`. `PlaceModel`'s `validateUrl` only accepts absolute http(s) URLs, so the local admin needs `STORAGE_LOCAL_URL_PREFIX=http://localhost:3000/uploads` or saved photo URLs become null.
- S3 bucket `eastvillageeverything-uploads` (us-east-1) is versioned. The IAM user `eve-uploads` can only Put/Delete under `public/*` and cannot delete object versions; use root to purge. Its keys live in root `.env` as `STORAGE_AWS_ACCESS_KEY_ID` / `STORAGE_AWS_SECRET_ACCESS_KEY`.
- Local iOS builds need `SENTRY_AUTH_TOKEN` exported from root `.env` (`SENTRY_KEY`). EAS secrets are not delivered to local builds. See apps/mobile/README.md.
- Server typecheck needs the workspace packages built first: `npm run build:packages` then `npx tsc --noEmit`. See CLAUDE.md.
- The production site is `eastvillageeverything.nyc`. The `.com` domain is not ours.
- The deploy workflow rewrites `/srv/eve/.env` on every run. Anything that must persist on the host goes in a separate file.
- Since 1.3, `app` and `admin` in `deploy/docker-compose.prod.yml` both have `env_file: [.env, .env.storage]`. Anything the deploy workflow writes to `/srv/eve/.env` (such as `CORS_ORIGINS`) and anything in the host-only `/srv/eve/.env.storage` reaches both containers. `environment:` entries still win over `env_file` values.
