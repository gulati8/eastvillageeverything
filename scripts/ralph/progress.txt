## Codebase Patterns
- Local admin run for browser checks: `npm run dev:admin` (Next on :3001; Postgres 5435 / Redis 6381 containers from `npm run dev:all` or docker; `apps/admin/.env.local` holds DATABASE_URL, REDIS_URL, SESSION_SECRET, storage vars, NEXT_PUBLIC_API_BASE_URL). Use `NEXT_PUBLIC_BASE_PATH=/admin npm run dev` in `apps/admin` when a check uses prod-shaped `/admin/...` URLs. Mint a session with a small script (`/tmp/eve-admin-test/session.mjs` in earlier runs; recreate it if gone): sign a random sid with `cookie-signature` using `SESSION_SECRET` from `apps/admin/.env.local`, write `sess:<sid>` to Redis 6381 as the JSON the Express login writes (admin user's id/email), and send cookie `connect.sid=s:<signed>`. Drive the installed Google Chrome with Playwright (`chromium.launch({ channel: 'chrome' })`, `isMobile: true` for 390x844). In a Playwright script `button[type=submit]` matches the header's Sign out form first; scope to `main button[type=submit]`. On a phone-height viewport the bottom notice stack covers the sticky Save bar for the 4 s a success card is up; dismiss it or wait before clicking Save.
- Admin feedback overlay: `components/Notices.tsx` (`NoticesProvider` + `useNotices().notify/dismiss`, mounted in `app/layout.tsx`) renders the bottom stack; pure reducer in `lib/notices.ts` (`node --test lib/notices.test.mjs`). `notify({ kind, title, detail?, action?, sticky? })` returns an id. Server actions call `await setFlash(kind, title, detail?)` (`lib/flash.ts`, cookie `eve_flash`) right before every `redirect(`; `components/FlashNotice.tsx` reads and clears it. Forms carry `<ReturnTo />` (hidden `return_to`, sanitized with `sanitizeAdminNextPath(value, fallback)`). `reorderTags` and the `*Inline` actions return `ActionResult` (`{ ok: true, ... } | { ok: false, error }`); callers wrap the call in try/catch and `notify`. `security.test.mjs` (`cd apps/admin && npm run test:security`, node:test over the source text) asserts the guard is the first statement of every mutating action and that every exported action that calls `redirect(` also calls `setFlash(`; add new action names and routes there.
- Admin server actions (`apps/admin/lib/actions/{places,tags,neighborhoods,photos}.ts`) follow one shape: `await requireAdminMutation()`, read the FormData, validate with `setFlash('error', …)` + `redirect(returnTo)` on failure, write through `@eve/db`, `revalidatePath`, `setFlash('success', …)`, `redirect`. `updatePlace` redirects back to `/places/<id>/edit`; `createPlace` to the new place's edit page. Known gap, not in any task: `readForm` in `lib/actions/places.ts` maps a blank text field to `undefined`, so clearing a field in the form does not clear the column.
- Admin API routes (`apps/admin/app/api/admin/{tags,uploads,version}/route.ts`) guard with `requireAdminRequest(req)` or `requireAdminRequest(req, { mutation: true })` (adds the Origin/Host check) and answer errors through `adminErrorResponse(err)`. The middleware answers signed-out `/api/*` requests with JSON 401 `Signed out` (pages still 307 to login). Client code builds URLs with `const basePath = process.env.NEXT_PUBLIC_BASE_PATH ?? ''` (`/admin` in prod).
- Pending state: `components/SubmitButton.tsx` (`useFormStatus`, must sit inside the form it reports on) is the submit button for every admin form; it also reads `useStale()` (`components/VersionWatch.tsx`, `lib/stale.ts`) to disable itself as "Reload first" after a redeploy is detected.
- Photo strip: `components/PlacePhotos.tsx` (client, rendered by the edit page above `PlaceForm`, outside the form) owns the place's photos: a full-width "Add photo" button under the heading plus a horizontal strip of cards; uploads with `XMLHttpRequest` to `/api/admin/uploads` (`file`, `prefix=place`, `place_id`); the first photo is "Featured", others carry a "Feature" button. `lib/photos.ts` holds `toPlacePhotoResponse`, `API_BASE` (`NEXT_PUBLIC_API_BASE_URL`, empty in prod) and `googlePhotoUrl(placeId, size)`.
- Place form: `components/PlaceForm.tsx` (client) renders Basics, "Tags in mobile order" (`TagPicker`, hidden input `tag_ids` = JSON array of ids), "Current web fields" (specials, notes), "Editorial for mobile" (pitch, perfect, insider, vibe, crowd), and an aside with Readiness and Guardrails cards; the sticky Save bar is below the grid. `defaultValues` come from the edit page (`app/places/[id]/edit/page.tsx`), which also loads the place with `PlaceModel.findById` (has `hours_json`, `price_tier`, `tags` as slug values, `neighborhood_id`, `google_place_id`).
- Design tokens for the admin come from `@eve/design-tokens` through `apps/admin/tailwind.config.ts`: colours `paper`, `paper2`, `ink`, `ink2`, `ink3`, `hairline`, `accent`; radii `rounded-chip|input|card|sheet`; the `.ui` class is the Schibsted Grotesk UI face (`globals.css`); headings are Instrument Serif italic by default. No dark theme in the admin.
- Tag slugs: `tags.value` is the slug; `place_tags` links by `tag_id`; the public site renders the filter dropdown and per-row CSS classes from `tag.value` on every load (`src/routes/public.ts`, `src/views/public/index.ejs`); the mobile app matches chip `value` against `place.tags` from the same API fetch (`apps/mobile/src/state/useFilterState.ts`), in memory only. `GET /api/places?tag=<slug>` filters by slug. Nothing stores a slug long-term, so a slug may change with the display name.
- Editorial voice rules and the batch validator live in `scripts/ralph/editorial-append.mjs` (two-sentence pitch split rule, banned words, 12-word limit for `perfect`); the archived launch plan task 3.5 has the full rule text. Every prod place has `pitch`, `perfect`, `insider` from that batch; `vibe` and `crowd` are blank everywhere.
- Prod shell checks: `ssh ec2-user@100.29.233.41`; containers `eve-app`, `eve-admin`, `eve-db`, `eve-redis`; compose dir `/srv/eve` (file `deploy/docker-compose.prod.yml`, the admin service reads `/srv/eve/.env` and `.env.storage` through `env_file`); `sudo docker exec eve-db psql -U eve -d eve_production -tAc "<sql>"`; `docker logs -t eve-admin --since 48h`. The deploy workflow rewrites `/srv/eve/.env` on every deploy from GitHub Actions secrets, so a new env var must be added there, not by hand on the host.
- Secrets: the root `.env` is gitignored and holds `ANTHROPIC_API_KEY`, `GOOGLE_PLACES_API_KEY`, `SENTRY_KEY`, `ASC_*`, `STORAGE_AWS_*`. Next.js reads `apps/admin/.env.local` (gitignored), not the root file; copy a variable across by piping (`grep '^NAME=' .env >> apps/admin/.env.local`), never by echoing its value.
